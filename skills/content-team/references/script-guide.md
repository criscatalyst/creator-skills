# How to write the scripts

A script here is 45 to 55 seconds, 130 to 150 spoken words. Write it to be said, then read it aloud once: anything you trip on, rewrite.

## The nine beats

| Beat | Job |
|---|---|
| 1. Hook | Start from what the viewer wants, then the thing that gets it |
| 2. Proof | Something real, shown on screen |
| 3. Re-hook | A second benefit they didn't expect |
| 4. Preview | "Here's how you can do the same in three steps." |
| 5. Step one | What the viewer does first |
| 6. Step two | What the viewer does next |
| 7. Step three | What they get |
| 8. Payoff | The biggest benefit, said once, plainly |
| 9. Call to action | In the user's own wording |

## Hook

The hook decides everything. Write 5, keep the one that would stop you.

- **Open on the viewer's goal, not on the tool.** "If you want more clients you have to post more videos, so here's an AI skill that lets you legally steal your competitors' viral reels." The tool arrives at the end of the sentence, as the way to get what they want.
- **The benefit is in the sentence.** If you can't point at the words that say what the viewer gains, it's a description, not a hook.
- **At least one word with weight**: steal, delete, free, stop, never, a real number, a real duration. Not "amazing", not "insane".
- **Surprising but believable.** One word can make a wild claim safe to believe ("legally steal").
- **Plain words for outsiders.** "An AI skill", not the name of a feature only insiders know.
- A long sentence is fine if it runs in one breath: goal, what it takes, "so here's" the fix.

Each hook comes in three layers: the spoken line, the text on screen (6 words at most, and not the same words as the voice), and the first frame. The first frame is the pattern interrupt: a movement, an object, a result already on screen. Never a title card.

## Proof

One real thing: a number the user has, a screenshot, the output itself. It must come from `profile.md`, from `~/CLAUDE.md`, or from the user. If you don't have it, write `[YOUR PROOF: what goes here]` and list it under "To prepare". **Never invent a number, a result or a story.**

## Steps

- Announce them in a full sentence, then "Step one", "Step two", "Finally, step three".
- Each step is something the viewer does, in their own terms ("you send Claude the link to your profile"), plus what they get from it. How the tool works inside stays out, or goes on screen.
- No lines that talk about the script itself: no "but that's the boring part", no "here's where it gets good", no "wait for step two". The content holds the attention or the line gets cut.
- If the user's calls to action use a comment keyword, plant it in step one ("comment X and I'll send it to you") and repeat it at the end.

## Payoff

The last line before the call to action is the biggest thing the viewer walks away with. Write it fresh for this script: don't reuse the shape of another script's payoff. It has to stay true for what the video actually shows.

## Voice

- Use the words and the sentence shapes quoted in `profile.md`. If the user says "guys", write "guys". If they never do, don't.
- Contractions everywhere. Round numbers the way people say them ("almost 4 million").
- Let sentences run and join them with "and" or "so". Short fragments stacked on each other read like a list.
- Out: em dashes, "it's not X, it's Y" more than once, three parallel items in a row, and words like "seamless", "game-changer", "unlock the power", "in today's world".

## Output, per script

```
SOURCE: link · @account · views · N x their median · days ago
WHY IT WORKED: one line on the mechanism, not on the topic

HOOKS
1. spoken / on-screen text / first frame
2. ...
3. ...

SCRIPT
(the spoken text, one beat per paragraph)

ON SCREEN: what the viewer sees at each beat, one line each

CAPTION: in the user's caption style, from profile.md

TO PREPARE: every proof, recording or resource the script promises and that doesn't exist yet
```
