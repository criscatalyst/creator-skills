# Writing Rules — the final filter

Run this over every post before delivering. These rules **clean** a post, they don't rewrite it. The structure and the user's voice stay; the AI tells come out.

## The non-negotiables

1. **No em dashes (—).** Ever. Replace with a period or a comma. This is the single biggest AI tell.
2. **Every thread part ≤ 280 characters.** Twitter caps at 280, Threads at 500. Stay under 280 so one text serves both. Over 280 → split or trim.
3. **One idea per line.** Hard line breaks. White space is a feature on Threads.
4. **≤ 25 words per sentence. 5th-grade reading level.** Short words. If it sounds like an essay, cut it.
5. **No all-caps phrases.** "REAL TALK:", "SERIOUSLY!", "LISTEN UP" → lowercase + a line break ("Real one.").
6. **Max 3 emoji in a whole thread.** Never 🚀 or 🔥. A single, real emoji beats a sprinkle.
7. **Never fabricate.** No invented numbers, deals, wins, or before/afters. Verifiable first-person only.

## Vocabulary ban (AI tells)

Strip or replace: delve, leverage (as filler), unlock, elevate, supercharge, game-changer, in today's world, the truth is, it's important to note, navigate the landscape, robust, seamless, harness the power, embark, tapestry, testament, realm, foster, paradigm. Also kill hedging: "I think maybe", "it could be argued", "in some sense".

## Contractions

Always contract. "I have" → "I've", "you are" → "you're", "do not" → "don't". Formal uncontracted English reads as AI.

## Specificity rule — depends on post type

- **Take / observation / mic-drop:** generic is the point. Do NOT add fake specificity. Just clean vocabulary + contractions.
- **Value thread / how-to:** one real, concrete detail per part. Names of real tools, real numbers, real steps.
- **Build-in-public / proof:** show exactly what was done. Concrete > clever.

Don't force "burstiness," don't avoid the number 3 on principle, don't turn a take into a story. The post type sets the rules.

## Tool-honesty rule

If they used an existing tool (a SaaS, an app), name it plainly. If they built the thing themselves, they can flex it. Never imply they built something that's off-the-shelf, and never hide a real tool to sound more impressive. Credibility is the asset.

## Human + AI attribution

When a post describes an AI-assisted workflow, never give the impression "the AI did everything." The honest and more credible framing is: **human input/idea/taste → AI structuring/scale → human selection.** This reads as real and dodges the "slop" perception.

## Quality gate (check before delivering each post)

- [ ] No em dash anywhere
- [ ] Every thread part ≤ 280 chars
- [ ] "I" or "you" in the first 3 lines
- [ ] ≤ 25 words per sentence
- [ ] ≥ 2 power verbs in the hook
- [ ] Hook archetype chosen on purpose
- [ ] No banned vocabulary, contractions applied
- [ ] No all-caps phrases, ≤ 3 emoji, no 🚀/🔥
- [ ] Claims verifiable and first-person
- [ ] Specificity matches the post type
- [ ] One post = one job

If `~/CLAUDE.md` has the user's own voice / anti-slop rules, those **override** the generic guidance here. The point is to sound like them.
